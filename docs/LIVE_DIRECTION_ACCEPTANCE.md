# Live演出の実LLM代表ケース（#46／#266）

対象は現在のアプリ → 選択済み演出LLM → 接続中のBlender GUI → 実状態の読戻し。旧headless試験の結果を本経路の合格に流用しない。判定仕様は[設計書](IMPLEMENTATION_PLAN.md)の「Live Blender」節を参照する。以下は実行手順であり、実施済み記録ではない。

## 準備

1. 検証対象commitでMacアプリを起動し、試験用の別作品と、カメラ・被写体を持つ作業用blendを用意する。利用者の制作中作品・採用checkpointを編集用に使わない。
2. 既に利用者が選択した演出LLMを接続する。最初は既存のローカルOllamaモデルを使い、モデルを勝手に取得・変更しない。クラウドへの自動退避は行わない。
3. 試験コマを同じGUIへlive割当し、現在のカメラ・焦点距離・被写体を確認する。原稿、他コマ、採用作画の開始時の状態を残す。

## 少数の代表ケース

各ケースはアプリの修正欄から実行する。モデルの生応答だけを手動で実行する経路では代用しない。ケースの間に必要な状態へ戻す場合はGUIで明示的に操作し、アプリで再観測する。

| ケース | 指示と開始状態 | 確認すること |
|---|---|---|
| 相対的な変更 | 「もっと寄って」。カメラと被写体がある | 対象を観測し、操作があれば実値が変わり読戻しと一致する。未操作readyや不正応答は未達・具体的案内になる。変更後の構図は別途目視する |
| 逆方向の変更 | 「少し引いて」 | 上と同じ。固定のmm値に一致することを合格条件にしない |
| 明示目標と実値 | 現在35mmから「焦点距離を75mmにして」 | 75mmになったことを実値で確認するか、未達・理由・詳細調整への案内を表示する。35mmのまま成功としない |
| 変更不要 | 現在35mmから「焦点距離を35mmにして」 | 同値の実状態が照合されたときだけ「変更不要」。確認待ちのままで候補保存・採用は実行しない。モデルがblocked等を返した場合は未達として記録する |
| 未対応・不足 | 「存在しない人物の腕を上げて」 | 別の人物へ勝手に置き換えず停止し、対象指定／素材追加／詳細調整など利用可能な次の手段を案内する |

## 結果の残し方

`#266`にcommit、macOS／Blender／モデル版、各指示、開始・終了の実状態、runのstatus／failure／操作数／goal_evidence、画面、保存・再起動結果を記録する。token、APIキー、接続認証情報は記録しない。API障害の場合はモデルの日本語解釈を評価済みにしない。

判定を「操作適用」「変更不要を実値で確認」「適切な未達案内」「不正な成功表示」「未実施」に分ける。全ケースが停止しても、停止・案内だけの合格であり自然言語制作の成功ではない。実機で意図どおりの構図になったか、候補保存／明示採用／Undo／再起動で保持されるかは別に確認する。少なくとも一つの相対指示による実操作適用と見た目の確認が記録されるまで、自然言語制作を動作確認済みと報告しない。
