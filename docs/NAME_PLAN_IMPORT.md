# 原文入りネームの取込み

## 制作の入力

アプリへ渡すのは **番号付きネームJSONと人物IDに対応する参照画像**。原稿を別途取り込む必要はない。原稿の編集はstory-libraryで行う。

1. Manga Directorで `works/<workId>/manga/<episodeId>/name-001.json` を作る。前半・後半など任意の範囲を `name-002.json` 以降へ分けられる。番号は1〜999999で、3桁未満をゼロ埋めする。
2. アプリの「ネームJSONを開く」で候補を読み、仮ネームを確認して採用する。GitHubでは作品・話・番号を選び「番号付きネームを開く」。原稿本文の取得は不要。
3. 「人物の参照画像」で `yumi` など固定IDの欄に画像を登録する。画像の順序や変更前のhashは照合しない。差し替え後は次の作画から新しい画像を使う。
4. 「ネームJSONを追加」で別番号を採用する。同じ話は番号順に並ぶ。別番号のコマ・作画・手動配置は残る。同じ番号は「この番号を更新」で置き換える。
5. 「採用したネーム」で制作対象を選ぶ。画像不足は該当する人物IDを表示し、そのコマを未作画のまま残す。他のコマは制作できる。

## データと検証

`manga-mac/name-plan/v2` の `source.kind: "embedded"` を使う。

- `source.scenes[].text`: 作成時点の原文。コードが読込時の原文をコピーする。
- `source.selectedAtomIds`: この番号が漫画化する範囲。コマはそのatomを参照する。
- `source.characters`: 使用する固定人物IDと表示名。画像の順番から人物を割り当てない。
- `source.episodeId` / `number`: 話とネーム番号。`source.commit` は任意の来歴。

最新原稿・設定・人物画像とのhash一致は取込条件にしない。原稿を改稿しても、保存ネームの原文は自動変更されない。ファイル形式、存在しないatom/人物ID、台詞の欠落、配置破損はそのネーム内で検査する。

内部では既存SourceRef・renderer・SQLiteを再利用するため、ネーム内原文の保存版を作る。内部保存の破損検査や送信済みJobの同一性は維持するが、最新の原稿との同期や画像キャッシュは不要。

採用中は `namePlan`、他の番号は `otherNamePlans` に一度ずつ保存する。既存のUndo・初稿履歴・Jobとともに保存・復元する。候補を開くだけで作画しない。

## 旧形式

原文を含まない旧v1/v2は、当時の原稿を持つ既存作品の読取互換として残す。最新原稿に位置だけを無条件で結び直さない。新しい原稿不要の入口では、Manga Directorから原文入りの番号付きネームを書き出す。

## 開発時の確認

`node tools/manga-director/validate.mjs --plan name-001.json` で原稿なしの構造・原文対応・配置検証を行える。AI接続・画像生成は使わない。旧形式に限り `--project PROJECT.json --source-bundle SOURCE.json` を指定する。
