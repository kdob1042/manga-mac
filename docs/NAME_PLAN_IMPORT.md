# ネームを作り、漫画制作へ渡す

主経路はstory-libraryのManga Director Skillを読むチャットAI。原稿理解・ページ／コマ構成・レビュー・脚本改善提案は同じチャット内で行う。manga-macや独自のAI実行CLIを起動してそのループを回す必要はない。

## チャットからGitHubへ

Skill正本は `kdob1042/story-library/skills/manga-director/SKILL.md`。同じ作品版の原稿・設定を読み、候補をレビューする。保存を依頼された場合は、原稿変更（必要な場合）と対応する `works/<workId>/manga/<episodeId>/name-plan.json` を同じ作業PRへ保存する。作品固有差分は任意の `works/<workId>/manga-director.md`。マージと公開は別操作。

`manga-mac/name-plan/v2` の意味構造・掲載文字・原稿対応は共通契約で検査する。`source.commit` は任意の生成時来歴で、自身を含む未来のcommitを記入する必要はない。省略しても本文・設定・人物のhash検査は省略されない。取得commitはアプリ側が記録する。

## アプリで受け取る

1. 原稿を取り込み、使用中の原稿ブランチと話を確認する。
2. 「制作する場面・保存した原稿」を開き、「同じGitHub版のネームを読み込む」を押す。`works/<workId>/manga/<episodeId>/name-plan.json` を**取り込んだ原稿のSHA**から取得する。GitHubへ保存したばかりの新版は、先に原稿の更新確認・取込が必要。
3. ファイル取得と検査の後、候補だけを保存する。原稿・既存ページ・作画は採用前に変更しない。前後の話をread-only文脈として参照できるが、別の話を漫画化対象に混ぜたファイルは拒否する。
4. ページ数・原稿の掲載方針・実文字入り仮ネームを確認する。座標compilerは候補作成時に動くため、**採用前に**文字溢れ・対象外ページとの衝突を確認できる。解なしを無難な4コマへ黙って変えない。
5. 「このネーム候補を採用」または「旧稿を残して別初稿に採用」を選ぶ。取得・確認・採用だけでは作画／動画生成・公開しない。
6. 「このネームで制作」で、既存の画像モデル／人物参照を使い、確定ページを維持して作画・文字配置・初稿表示へ進む。

手動のネームJSONファイルも同じ候補経路へ渡せる。アプリ内の設定済み演出AIによる候補生成は任意の別入口であり、GitHub取込の前提ではない。旧v1は空の原稿への取り込み互換を維持する。

## ローカルの検証コマンド

開発時には `node tools/manga-director/validate.mjs --project PROJECT.json --plan name-plan.json --source-bundle SOURCE.json` で、取込前に形式・原稿対応・組版を診断できる。PROJECTは取り込み済みproject JSON、SOURCEは `{"manifest":story-sourceのmanifest,"files":{"作品rootからの相対パス":"ファイル本文"}}` 形式。source-bundleの本文を取り込み済み原稿と照合し、共通story-source validatorとアプリ本番のv2 importer/compilerを実行する。成功時は形式、コマ／ページ数、ファイルhashをJSONで表示し、入力ファイルは変更しない。

このコマンドはローカルの診断だけを行う。GitHub取得SHAの固定と候補の保存・明示採用はアプリの操作で行う。LLM、別ホストのAPI、APIキー、画像生成、公開は使用しない。

## 更新と制約

原稿・設定・人物参照の不一致、別作品、未対応形式、巨大JSON、取得途中の原稿版変更は候補・採用前に停止する。ファイルがない場合や認証に失敗した場合、別HEAD／別パスや別AIへ自動退避しない。トークンは既存のメモリ上の読み取り専用設定を使い、ネーム・来歴に保存しない。

局所編集の指示は候補として確認する。枠だけなら画像は再生成しない。手動枠と固定ページは既存エディタ・Undoを使い、旧意味計画から巻き戻さない。原稿更新時は旧漫画を保って再確認へ戻り、原稿をアプリから書き換えない。

視覚QAは画像入力対応接続と、ページ画像送信の明示許可がある場合だけ実行する。機械検査、AIの指摘、人が読む評価を区別する。仮ネームは作画プレースホルダーであり完成画像ではない。

自動compilerはページ内に収まる非重複の凸四角形を使う。斜辺は二つのleaf間、insetは非重複の小コマ。曲線・複雑な重なり・印刷裁ち落としを無断で単純枠へ変換しない。
