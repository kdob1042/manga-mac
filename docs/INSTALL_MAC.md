# Mac購入後のインストール・初回設定

このアプリはMacにインストールするデスクトップアプリです。配布DMGを使う手順では、Xcode・Node.js・Rust・Python・Homebrew・GitHub Desktopは不要です。

> **このガイドの対象**：以下は現行の2D制作版の手順です。[設計・実装計画 v4.0](IMPLEMENTATION_PLAN.md) のBlender連携は未実装であり、Blenderを追加インストールするだけで現行版に3D機能が使えるようになるわけではありません。目標構成では同じMacにインストールした対応版Blenderと、検証済みのMCP／接続拡張を利用します。対応版・接続設定・導入手順は実装と検証後に本ガイドへ追加します。Tripo等の3D生成サービスは任意で、利用時だけ別途API認証・通信・料金が必要です。現行版のLLM接続先選択と、今後の画像生成先・3D生成先の選択は別機能です。

> **配布状況（2026-09-14確認）**：最新mainビルドは実行中、直前のmainビルドは失敗。最新実行で確認できたのはUIテスト成果物のみで、DMGはまだ確認できていません。以下のインストール手順は、Macビルドが成功してDMGが作られた後に使います。実機の初回起動・生成も未検証です。現在の状況は[Actions](https://github.com/kdob1042/manga-mac/actions/workflows/check.yml)を確認してください。

## 1. Macで用意するもの

- Apple Silicon搭載Mac（Mシリーズ）、macOS 14以降。Intel Mac向け配布はありません。
- 初回ダウンロード用のインターネット接続。
- この非公開リポジトリを閲覧できるGitHubアカウント。
- キャラクターの正本画像（PNG/JPEG/WebP、1枚20MB以下）。
- 外部LLMを使うなら、利用先のAPIキーとモデルID。

24GBメモリでの実際の生成速度・ピーク使用量は未測定です。モデルと作品はアプリ本体とは別に容量を使います。固定の必要容量はまだ確定していないため、ダウンロード時に空き容量を確認してください。

## 2. アプリをダウンロードする

1. MacのブラウザでGitHubへログインします。
2. [Manga MacのActions](https://github.com/kdob1042/manga-mac/actions/workflows/check.yml)を開きます。
3. **mainブランチの、成功した実行**を開きます。実行中や失敗のものは選びません。
4. 実行画面の **Artifacts** から `Manga-Mac-Apple-Silicon-unsigned` をクリックします。
5. ダウンロードしたZIPをダブルクリックで展開し、中の `.dmg` を開きます。

`UI-test-results` は画面テストの結果で、インストーラではありません。`Code → Download ZIP` はソースコードなので、通常のインストールには使いません。現段階ではGitHub Releasesへの自動配布もありません。

配布物が見つからない場合：
- ログインしているか、mainの成功実行かを確認します。
- `mac` ジョブの成功とDMG成果物の存在を確認します。
- 配布物が期限切れなら、このワークフローの **Run workflow → main** で再ビルドできます。
- ビルド失敗なら、アプリ側の修正が必要です。Macに開発ツールを追加して解決する手順ではありません。

成果物はログイン済み・リポジトリ閲覧権限のあるユーザーが取得できます。[GitHub公式手順](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts)

## 3. アプリケーションフォルダへ入れる

1. DMGの中の **Manga Mac.app** を、Finderの **アプリケーション（Applications）** へドラッグします。
2. コピー完了後にDMGを取り出します。
3. アプリケーションフォルダから **Manga Mac** を開きます。以後はDockへ追加して起動できます。

初期配布はDeveloper ID署名・Apple公証が未設定です。「開発元を確認できない」などで起動が止まる場合、このリポジトリのビルドから取得したものと確認したうえで、一度起動を試し、**システム設定 → プライバシーとセキュリティ → このまま開く**を選びます。表示されない場合や「破損」「コンピュータに損害を与える」など別の警告なら、警告の全文を添えて報告してください。端末全体の保護機能を無効にする必要はありません。[Apple公式手順](https://support.apple.com/ja-jp/102445)

## 4. LLMを設定する

アプリの **接続・人物設定 → AIの接続** を開きます。「演出・コマ計画」と「顔の範囲推定」は別々に設定できます。

### A. 外部APIを使う

1. 接続先からOpenAI / Gemini / Claude / DeepSeek / OpenAI互換APIを選びます。
2. 利用可能なモデルIDとAPIキーを入力します。
3. **接続をテスト**を押します。
4. 顔の自動選択にも外部APIを使う場合は、そちらにも画像入力対応モデルとキーを設定します。

両方を外部APIにするならOllamaは不要です。演出APIには脚本・設定・人物説明、顔推定APIには生成画像・対象人物の正本画像が送られます。APIの利用料金は別途発生します。画像を描くFLUX自体はMac内で動きます。

現在、APIキーとLLMの接続設定は起動中だけ保持されます。**アプリを終了すると再入力が必要**です。「接続をテスト」はJSONのテキスト応答の確認で、画像入力の動作までは確認しません。

### B. ローカルのOllamaを使う

1. [OllamaのMac版](https://ollama.com/download/mac)をダウンロードします。
2. Ollama.appをアプリケーションフォルダへ入れて起動します。
3. 初回のコマンドライン設定が表示されたら、公式の案内に従います。
4. Macの「ターミナル」を開き、使用する用途のモデルだけ取得します。

```sh
# 演出・コマ計画をローカルで行う場合
ollama pull qwen3:8b

# 顔の範囲推定もローカルで行う場合
ollama pull qwen3-vl:4b
```

5. Manga Macで該当用途を **Ollama（ローカル）** にし、上記のモデルIDを入力します。
6. **接続をテスト**を押します。利用中はOllamaを起動しておきます。

ターミナルが必要なのはこのローカルモデルの取得です。アプリ本体をソースからビルドする作業ではありません。外部APIとOllamaを用途ごとに混在させても使えます。[Ollama公式のMac導入手順](https://docs.ollama.com/macos)

## 5. 原作をGitHubから取り込む

**接続・人物設定**で入力します。

| 項目 | 「神谷と河合」の例 |
|---|---|
| GitHubリポジトリ | `kdob1042/Kamiya-Kawai` |
| 話ID | `P01`（まず第1話） |
| トークン | 原作リポジトリの読み取り用トークン |

非公開原作の場合、GitHubの **Settings → Developer settings → Personal access tokens → Fine-grained tokens** で作成します。対象は `Kamiya-Kawai` のみを選び、Repository permissionsの **Contents: Read-only** を付けます。漫画アプリは原作へ書き戻しません。

**更新を確認する → この版を取り込む**を押します。ブラウザでGitHubへログインすることと、アプリに原作用トークンを入力することは別です。原作用トークンもアプリ終了後は再入力が必要です。

## 6. キャラと画像モデルを準備する

1. 人物名と髪型・衣装などの固定特徴を入力します。
2. **正本画像を登録**で画像を選びます。複数の主要人物が登場するなら、それぞれ登録します。
3. **画像モデルを準備する**を押し、FLUX.2 klein 4Bのダウンロード完了を待ちます。

画像モデルの準備は、LLMを外部APIにした場合も必要です。既存の参照を別人物へ置き換える機能はまだないため、名前と画像の対応を確認して登録してください。

## 7. 最初の制作と保存

1. **漫画にする**を押します。演出計画から順にコマを作画します。
2. コマが完成するたびに作品は自動保存されます。
3. 表情修正はコマ・対象人物を選んで自然言語で指示します。顔を特定できない場合は画像をドラッグして変更領域を指定します。
4. 取り消す場合は **元に戻す**を使います。
5. **PNG** または **CBZを書き出す**で出力します。

出力先はFinderの **ダウンロード → Manga Mac** です。日時付きのファイル名になります。長い文字が入り切らない場合は省略せずエラーになるため、現在の初期版では書き出せない原稿構成もあります。

## 困ったとき

| 症状 | 確認すること |
|---|---|
| DMGがない | mainのMacビルド成功とArtifactsを確認 |
| LLMに接続できない | 選択先、モデルID、APIキー、またはOllamaの起動 |
| GitHub 401 / 403 / 404 | 原作名、トークンの対象リポジトリ・期限・Contents権限 |
| 画像エンジンがない | 正式なMacビルド成果物か確認。UIテスト用成果物では動きません |
| モデル準備・生成が失敗 | エラー全文、Macのチップ・メモリ、macOS版、アプリの取得元実行URLを控える |
| 再起動後に接続できない | API設定とGitHubトークンを再入力 |

報告時はAPIキー・GitHubトークンを貼らず、エラー表示とビルド実行URLを共有してください。
