# Mac購入後のインストール・初回設定

このアプリはMacにインストールするデスクトップアプリです。配布DMGを使う手順では、Xcode・Node.js・Rust・Python・Homebrew・GitHub Desktopは不要です。

> **このガイドの対象**：mainには2D制作に加え、Blender接続・撮影・漫画化候補・動画生成経路の実装候補があります。配布DMGに含まれる範囲は、そのDMGの生成元コミットで確認してください。Mac実機での初回起動・画質・24GB性能は未検証です。基本の2D導入手順に続き、後半の「追加実装の試用手順」「動画候補の試用」を参照してください。外部LLM・画像生成・動画生成・任意のTripoは用途と料金が異なります。

> **配布状況（2026-09-14確認）**：段階Aの[PR #6のCI](https://github.com/kdob1042/manga-mac/actions/runs/34824097915)でApple Silicon向け未署名DMGの生成を確認しました。mainの配布は、マージ後の成功実行とDMG成果物を確認して取得してください。実機のインストール・初回起動・画像生成・性能は未検証です。

## 1. Macで用意するもの

- Apple Silicon搭載Mac（Mシリーズ）、macOS 14以降。Intel Mac向け配布はありません。
- 初回ダウンロード用のインターネット接続。
- ActionsのDMG成果物をダウンロードするGitHubアカウント（コードのリポジトリは公開）。
- キャラクターの正本画像（PNG/JPEG/WebP、1枚20MB以下）。
- 外部LLMを使うなら、利用先のAPIキーとモデルID。

24GBメモリでの実際の生成速度・ピーク使用量は未測定です。モデルと作品はアプリ本体とは別に容量を使います。固定の必要容量はまだ確定していないため、ダウンロード時に空き容量を確認してください。

## 2. アプリをダウンロードする

1. MacのブラウザでGitHubへログインします。
2. [Manga MacのActions](https://github.com/kdob1042/manga-mac/actions/workflows/check.yml)を開きます。
3. **mainブランチの、成功した実行**を開きます。実行中や失敗のものは選びません。
4. 実行画面の **Artifacts** から `Manga-Mac-Apple-Silicon-unsigned` をクリックします。
5. ダウンロードしたZIPをダブルクリックで展開し、中の `.dmg` を開きます。

`UI-test-results` は画面テストの結果で、インストーラではありません。`Code → Download ZIP` はソースコードなので、通常のインストールには使いません。現段階ではGitHub Releasesへの自動配布もありません。

配布物が見つからない場合：
- ログインしているか、mainの成功実行かを確認します。
- `macOS release package` ジョブの成功とDMG成果物の存在を確認します。統合後のMac検証は`dev`の`macOS validation`で確認します。
- 配布物が期限切れなら、このワークフローの **Run workflow → main** で再ビルドできます。
- ビルド失敗なら、アプリ側の修正が必要です。Macに開発ツールを追加して解決する手順ではありません。

成果物はログイン済み・リポジトリ閲覧権限のあるユーザーが取得できます。[GitHub公式手順](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts)

## 3. アプリケーションフォルダへ入れる

1. DMGの中の **Manga Mac.app** を、Finderの **アプリケーション（Applications）** へドラッグします。
2. コピー完了後にDMGを取り出します。
3. アプリケーションフォルダから **Manga Mac** を開きます。以後はDockへ追加して起動できます。

初期配布はDeveloper ID署名・Apple公証が未設定です。「開発元を確認できない」などで起動が止まる場合、このリポジトリのビルドから取得したものと確認したうえで、一度起動を試し、**システム設定 → プライバシーとセキュリティ → このまま開く**を選びます。表示されない場合や「破損」「コンピュータに損害を与える」など別の警告なら、警告の全文を添えて報告してください。端末全体の保護機能を無効にする必要はありません。[Apple公式手順](https://support.apple.com/ja-jp/102445)

## 4. LLMを設定する

アプリの **接続・人物設定 → AIの接続** を開きます。「演出・コマ計画」の接続を設定します。Blender自動演出も同じ接続を使います。

### A. 外部APIを使う

1. 接続先からOpenAI / Gemini / Claude / DeepSeek / OpenAI互換APIを選びます。
2. 利用可能なモデルIDとAPIキーを入力します。
3. **接続をテスト**を押します。

演出を外部APIにするならOllamaは不要です。演出APIには脚本・設定・人物説明、Blender演出時には素材名・構図・操作結果も送ります。APIの利用料金は別途発生します。画像を描くFLUX自体はMac内で動きます。

現在、APIキーとLLMの接続設定は起動中だけ保持されます。**アプリを終了すると再入力が必要**です。「接続をテスト」はJSONのテキスト応答の確認で、画像入力の動作までは確認しません。

### B. ローカルのOllamaを使う

1. [OllamaのMac版](https://ollama.com/download/mac)をダウンロードします。
2. Ollama.appをアプリケーションフォルダへ入れて起動します。
3. 初回のコマンドライン設定が表示されたら、公式の案内に従います。
4. Macの「ターミナル」を開き、使用する用途のモデルだけ取得します。

```sh
# 演出・コマ計画をローカルで行う場合
ollama pull qwen3:8b
```

5. Manga Macで該当用途を **Ollama（ローカル）** にし、上記のモデルIDを入力します。
6. **接続をテスト**を押します。利用中はOllamaを起動しておきます。

ターミナルが必要なのはこのローカルモデルの取得です。アプリ本体をソースからビルドする作業ではありません。接続先は設定で切り替えられます。[Ollama公式のMac導入手順](https://docs.ollama.com/macos)

## 5. 原作をGitHubから取り込む

**接続・人物設定**で入力します。

| 項目 | 「神谷と河合」の例 |
|---|---|
| GitHubリポジトリ | `kdob1042/Kamiya-Kawai` |
| 話ID | `P01`（まず第1話） |
| トークン | 原作リポジトリの読み取り用トークン |

非公開原作の場合、GitHubの **Settings → Developer settings → Personal access tokens → Fine-grained tokens** で作成します。対象は `Kamiya-Kawai` のみを選び、Repository permissionsの **Contents: Read-only** を付けます。漫画アプリは原作へ書き戻しません。

**更新を確認する → この版を取り込む**を押します。ブラウザでGitHubへログインすることと、アプリに原作用トークンを入力することは別です。原作用トークンもアプリ終了後は再入力が必要です。

## 6. キャラと画像モデルを準備する

1. 人物名と髪型・衣装などの固定特徴を入力します。
2. **正本画像を登録**で画像を選びます。複数の主要人物が登場するなら、それぞれ登録します。
3. **画像モデルを準備する**を押し、FLUX.2 klein 4Bのダウンロード完了を待ちます。

画像モデルの準備は、LLMを外部APIにした場合も必要です。既存の参照を別人物へ置き換える機能はまだないため、名前と画像の対応を確認して登録してください。

## 7. 最初の制作と保存

1. **漫画にする**を押します。演出計画から順にコマを作画します。
2. コマが完成するたびに作品は自動保存されます。
3. 表情などの部分修正はコマ画像をドラッグして変更範囲を指定し、自然言語の指示を入力して適用します。顔推定AIは不要です。
4. 取り消す場合は **元に戻す**を使います。
5. **PNG** または **CBZを書き出す**で出力します。

出力先はFinderの **ダウンロード → Manga Mac** です。日時付きのファイル名になります。長い文字が入り切らない場合は省略せずエラーになるため、現在の初期版では書き出せない原稿構成もあります。

## 追加実装の試用手順（2026-09-16、実機未検証）

mainにBlender接続・素材検索・コマ別撮影・漫画化候補・文字配置が追加されています。冒頭の2D版DMGにこれらが含まれるとは限りません。対象mainコミットからCIが生成したDMGであることを確認してください。対応環境はBlender 4.5.13で、実機受入が終わるまで完成版とは扱いません。

1. 作品フォルダ全体をバックアップする。画像JSONだけではBlenderのチェックポイントは保存されません。
2. 設定でBlender実行ファイル、素材用の認可フォルダ、その中の舞台blendを指定して開く。初期のSceneにカメラが必要です。元素材は上書きしません。
3. 素材が不足する場合は「素材フォルダを再検索」からBlenderでアセット指定済みのObject/Collectionを選んで取り込む。リグを含む人物はCollection単位で準備してください。動画/UDIM/Geometry Nodes/シミュレーション等の未対応依存は明示エラーになります。
   Web配布素材は同じ画面の「Webの既存3D素材を取り込む」を開き、配布元でライセンスを確認して直接HTTPS URL、配布ページ、ライセンス名を入力します。URLに拡張子がなければ保存名を指定します。取得後にBlenderが検出した内容を選択して取り込みます。ログイン画面や商品ページのURLではなく、許可された素材ファイルのURLが必要です。
4. 制作方法を「Blenderで演出・撮影して作画」にして「漫画にする」。演出AIが素材・構図を読み、各コマの操作と撮影を進めます。手動のScene/Camera/frame調整と未確定要求の復旧は「詳細調整・Blenderの保存結果を確認」にあります。
5. 人物正本・必要な画風参照を用意します。自動制作は撮影後に漫画化へ進みます。対象コマへの新しい演出指示は「Blenderで演出して漫画化」で実行し、旧作画がある場合は候補を比較して採用します。
6. 顔を直す場合は完成画像上で矩形を指定する。専用顔推定や2回押しの操作はありません。カメラの変更は再撮影を伴います。
7. 文字配置を設定し「書き出しと同じページを確認」。作品言語が英語の場合は原作に対応する英訳が必要です。文字枠からあふれる場合は画像生成で直さず枠/コマ計画を調整する。
8. PNG/CBZを書き出す。フォルダ全体の復元・更新・実機性能は`docs/VALIDATION.md`のToDoを実施する。

応答未確定のBlender要求は「保存結果を採用」または「採用せず解決」で確認する。作品への撮影版保存が中断した場合は「保存済み撮影をこのコマへ接続」を使う。画像AIのunknownは旧原稿を保持し、解決前に再送しません。課金取消の保証ではありません。

24GB機向けにアプリが起動するBlenderとSwift画像処理は共通の実行ロックで直列化します。他のBlender/Ollamaプロセスのメモリを強制解放しません。24GBでの実測・署名/公証・クリーンインストールは未完了です。

## 動画候補の試用（有料実API・Mac内再生は未検証）

1. 「動画」で原作の場面と保存済みPNG作画/撮影を選ぶ。まだ画像がなければ「共有Blender素材から動画用に撮影」で専用ショットを作り、構図・素材を読込み、撮影後「この撮影を開始画像に使う」を押す。漫画コマを先に作る必要はない。同じ縦横比・5秒のショットを保存する。通常の正方形原稿は960:960を選ぶ。任意の縦横比からの自動切り抜きはしない。
2. 「動画API接続」でRunwayのAPIキー・作品の累計予約上限を指定し、送信内容を確認して登録する。アプリ内のLLM接続とは別。登録時点では有料要求を送らない。
3. 動きの案は既存の演出LLM、または直接入力で用意し、「指示を保存する」。生成ボタンで新規有料要求を1回送信する。
4. 「状態を更新」で確認し、生成成功後に「生成済み動画を取得」。再生して候補を採用する。MP4はDownloads/Manga Macへ保存する。
5. 再起動後は同じRunwayキーを再登録し、保存済みtaskを照会する。task ID未受領はサービス側で確認し、自動再POSTしない。取消・削除が完了済み結果を消す場合もあるため、確認表示を読む。
6. バックアップにはSQLite/artifacts/blenderに加えてmediaフォルダを含める。JSON書出しに動画本体は含まれない。動画取得直後に終了しても、保存済みartifactから候補を再接続する。

有料テストは利用者が用意した専用キー・予算内で実施する。現在の実装候補はRustビルド/実APIを未検証のため、先にVALIDATIONのV-C-NATIVE/HTTPを通す。料金はサービス側の設定でも制限・確認する。


### 画像生成後の終了から復旧する

新版helperを同梱したアプリでは、画像生成が完了してから画面保存までの間に終了した場合、対象コマの「保存済み作画を回収する」で結果を候補へ戻せます。回収は再生成せず、自動採用もしません。候補を確認して採用してください。局所編集は元画像と指定範囲から再合成します。生成が未完了・ファイルが欠損/破損・旧版の要求の場合は回収できない理由が表示されます。

バックアップは従来のSQLite/artifacts/blender/mediaに加え、`image-results`も含む作品フォルダ全体を保存してください。旧版へ戻すときは更新前のバックアップを復元します。Mac実helperの強制終了受入はVALIDATIONの`E-RECOVERY-MAC`に残っています。

## クラウドバックアップの初回設定・別Mac復旧（Issue #34）

初期状態は無効。実Google Drive/OneDriveへの往復・Keychain・Mac実機操作は未検証です。以下は実装候補の試用手順です。既存の契約済みクラウドを利用し、アプリから契約・課金プランの変更は行いません。

1. 本リポジトリの `scripts/install-backup-tools.sh` を取得し、内容を確認して実行します。Apple Silicon用のrestic **0.19.1** とrclone **1.75.1** を公式URLから取得し、コードに固定した配布元SHA-256を照合してから展開します。空の絶対パスを一つ指定します。例：`sh install-backup-tools.sh "$HOME/MangaBackupTools"`。sudo/開発ツール/常駐サーバーは不要です。既存フォルダには上書きしません。
2. `"$HOME/MangaBackupTools/rclone" config --config "$HOME/MangaBackupTools/rclone.conf"` を実行し、専用remote `manga` を作ります。typeは `drive` または `onedrive`。rcloneの通常ブラウザ認証を完了し、`chmod 600 "$HOME/MangaBackupTools/rclone.conf"` で自分だけ読書き可能にします。この初期版では暗号化されたrclone設定ファイルは未対応です。Drive等の一般同期クライアントでrestic repositoryを同時ミラーしないでください。
3. アプリの「接続・人物設定 → クラウドバックアップ → 保存先を設定・再接続」を開きます。保存先例：`rclone:manga:manga-mac-backups/works`。ツール2本と専用rclone.confの絶対パスを入力します。対象データ・週1回・旧版21日／最新保護を確認してください。
4. 新しい空の保存先に限り「初期化する」を選択します。12文字以上の復元パスワードを決め、**Mac以外のパスワード管理先にも保存**します。同じ保存先へ再接続する場合は初期化せず、以前と同じ復元パスワードを入力します。検査に成功した時だけ設定が有効になります。
5. 「今すぐバックアップ」で最終成功・全量検証日時を確認します。最初は「履歴を取得 → 別作品として復元 → この復元作品を開く」で、画像・動画・原文・履歴を確認します。切替は再起動を伴います。「元の作品を開く」で元へ戻れます。復元した作品の自動保存は未設定で、元系列を誤削除しません。

新しいMacでは同じツール導入・クラウド認証を済ませ、同じ保存先へ「初期化なし」で接続します。Keychainはバックアップに含まれないため、Mac外へ控えた復元パスワードが必要です。保存先履歴には全ての検証済み作品系列が表示されます。対象の日付・作品IDを確認して復元してください。新しい形式には対応版アプリが必要です。

Blenderは依存素材を既存packing機能で固定した保存版が対象です。未固定の素材は先に「開いて接続を確認」または撮影を完了してください。別Macへ復元後はBlender GUIへlive接続します。外部素材ライブラリ全体とWeb取得キャッシュ全体はバックアップの正本ではありませんが、保存版の再現に必要なpacking済み依存とdatablock上の出典・ライセンス・取得hashはcheckpointに含まれます。アプリが管理していないDownloads等の書き出しや、外部Blenderの未保存編集は含みません。

アプリが動いていない間は自動実行されません。起動・復帰後に期限を確認し、オフライン等の失敗は1時間間隔、2回失敗後は日次で再試行します。手動再試行もできます。新規保存に失敗した回は旧正常版を削除しません。旧版整理の失敗・容量回収未完了は別表示されます。クラウド側のゴミ箱やバージョン保持により、請求容量への反映が遅れる場合があります。クラウド全体のゴミ箱をアプリから空にすることはありません。

導入元：[restic 0.19.1](https://github.com/restic/restic/releases/tag/v0.19.1)（BSD-2-Clause）、[rclone 1.75.1](https://github.com/rclone/rclone/releases/tag/v1.75.1)（MIT）。初期版ではDMGへの同梱・暗黙の最新版取得は行わず、上記固定版を別途導入します。archiveは公式SHA256SUMS（2026-09-16取得）と照合しています。Keychainはsecurity-framework 3.7.0（MIT/Apache-2.0）を経由します。ツール更新時は公式配布物を再検証してアプリで再設定してください。

### 自由コマ割り版への更新

更新前の作品フォルダを保持してください。旧4コマ作品は既存の枠位置を維持して移行します。新しい自由レイアウトを保存した後、新版の保存処理はレイアウト欠落要求を拒否します。旧版アプリで新形式を編集しないでください。旧版へ戻す場合は更新前のフォルダを別の復元先へ戻してください。操作はREADME「自由なコマ割り」を参照。

## Live Mangaの配信用書き出し

FFmpeg/ffprobeが必要。Homebrew利用環境では `brew install ffmpeg`。アプリは標準のHomebrew配置またはPATHからffprobeを探す。未導入時は書き出しだけを停止して理由を表示し、既存の漫画制作・PNG/CBZ出力を妨げない。

生成動画のコンテナ名だけでは互換性を判断せず、実H.264・無音・寸法・尺・hashを検査する。出力先はDownloadsの`live-manga-<releaseId>`。新規出力はLive Manga v2対応読者を使用してください。v1対応読者は新形式を開けませんが、既存のv1刊行版はそのまま保持できます。この出力は配信用であり、編集用バックアップではない。既刊版の上書きやクラウド自動公開はしない。


### LTX-2.5 MLXでローカル動画を作る（実験的・#166）

Apple Silicon Mac専用です。24GBでのモデル実推論・性能は未受入です。API料金はかかりませんが、ディスク容量・メモリ・生成時間とモデル利用条件は別途必要です。

1. [ltx-2-mlx](https://github.com/dgrauet/ltx-2-mlx/tree/3d08a953957fbc4269093d4da2f88db5bc12f86b)を導入してください。接続実装が参照したcommitは`3d08a953957fbc4269093d4da2f88db5bc12f86b`です。Python 3.11以上・uv等の依存関係は同リポジトリの手順に従います。
2. [LTX-2.5 MLX q4 pack](https://huggingface.co/dgrauet/ltx-2.5-mlx-q4)の利用条件に同意し、tokenizer・設定・text encoder・connector・distilled transformer・VAE/音声部品・spatial_upscaler_x2_v1_0を含む一式をローカルへ取得してください。アプリはダウンロードや認証を代行しません。登録時のファイル検査は完全なモデル実行検証ではありません。
3. `brew install ffmpeg`等でFFmpegとffprobeを導入します。ffprobeはHomebrew標準パスまたはPATHに必要です。
4. 動画画面の「動画の生成先」を「LTX-2.5 MLX」に変更。`…/ltx-2-mlx/.venv/bin/ltx-2-mlx`、モデルフォルダ、FFmpegの**絶対パス**を入力し、信頼できる実行ファイル・利用条件を確認して登録します。設定は再起動後に再登録が必要です。
5. 開始画像を選び、ショットの寸法を512:512 / 512:320 / 320:512にして保存します。同じ縦横比のPNGが必要です。終端画像を使うA→Bは今回対象外。必要なら開始画像1枚の別ショットを作ります。
6. 「5秒の動画を生成する」。最大60分、他の重いAI処理と直列に動作します。完了後は候補を再生して確認し、明示的に採用します。結果は無音H.264 MP4です。

失敗時はモデル一式、上記CLI版との互換性、空きメモリ、FFmpeg/ffprobeを確認してください。自動再送・Runwayへの自動切替はしません。異常終了後のunknown要求は、Activity Monitorでltx-2-mlx・関連Python/FFmpegの停止を確認してから「採用せずローカルで解決する」を使用します。強制終了時は作品フォルダの`local-video-<UUID>`に未採用の途中ファイルが残る場合があります。アプリを閉じ、該当処理の停止を確認するまで触らないでください。

受入では実際の作画/撮影画像で生成→再生→採用→再起動→MP4書出しを試し、CLI commit・model pack・Mac機種/RAM・実行時間・最大メモリを記録してください。共通テストの疑似CLI/青い動画は、モデル実推論の確認には含めません。

### 制作途中の非公開プレビュー転送

「Live Mangaへ非公開プレビューを転送」を開き、対象作品／話を確認します。管理者が設定したHTTPS Worker originと、その作品／話だけに限定した転送用キーを入力してください。保存先は非公開Cloudflare R2です。R2管理キーは入力しません。初回の基準版は空欄です。転送済みの画面から次の版を送る場合は前回の現在版を引き継ぎます。他端末が更新して競合した場合は転送先の現在版を確認し、新しい転送を準備してください。

転送用キーは画面のメモリのみで保持し、作品／話を切り替えた際は引き継ぎません。「転送した版を閲覧する」で開くビューワーには、別の読み取り用キーで認証します。保存先・認証が未設定なら転送は失敗と表示し、公開URLへ迂回しません。

話全体の保存済みページを送ります。制作側のタグ検索は送信範囲を変えません。未作画・文字配置待ちは明示した途中稿として表示し、ページ未配置のコマは件数を示して除外します。転送中も制作を続けられます。失敗後は同じ転送版で「不足分から再開」を選び、再起動後は転送版IDと同じorigin／基準版を指定してください。転送準備にもFFmpeg/ffprobeが必要です。

実Cloudflareのbucket・Worker・認証設定、Macから別端末への実接続受入は別途必要です。この画面はクラウド構成や課金を自動設定しません。

### 対象場面・旧稿・保存した編集候補（PR #76）

「制作する場面・保存した原稿」で対象を選び、通常は「漫画にする」で続行します。原作版や制作範囲を変えるときは「既存原稿を残して別の初稿を作る」を選びます。旧稿は同じ欄から戻せます。未確定の作画要求は先に既存の復旧欄で解決してください。

## 開いているBlenderへのlive接続（#176）

1. リポジトリrootで `python3 scripts/package-live-addon.py` を実行し、生成された `dist/manga_mac_live.zip` をBlender 4.5の Preferences → Add-ons → Install from Diskで導入・有効化する。
2. 対象の編集用blendを自分で開く。3D ViewのNパネル → Manga Live → Start local connection。採用済みcheckpointそのものを編集用に開かない。アプリ保存領域の外へ作業用コピーを保存して開く（管理領域内のファイルとそのsymlinkへの接続は拒否される）。

tokenは作品へ保存されず、作品/原稿切替後の不一致対象への操作は拒否する。対象を確認し、明示切断・再接続する。上流の通常アドオンとは異なる限定版を使用し、同じportへ重ねて起動しない。新しい編集・撮影はGUIのみ。旧撮影はそのまま参照できます。Mac GUI実接続の受入はVALIDATIONを参照。

### 原稿・参照画像を渡し、角度候補を撮る

## Tripo任意接続（#201、実APIはMac実地確認で検証）

Tripoを使う場合だけ、設定の「Blenderで撮影する → 参照画像から3Dモデルを作る（Tripo・任意）」を開きます。APIキー、作品単位のcredits上限、送信内容への明示承認を入力して接続を登録します。登録だけでは画像を送信しません。APIキーは起動中のnativeメモリだけに保持し、作品JSON・blend・制作依頼ZIP・ログへ保存しません。アプリ再起動後は再入力します。

1. キャラクターの正本画像（PNG/JPEG/WebP、20MB以下）を選び、モデル版・送信対象・補足指示を確認して「参照画像からモデルを生成」を押す。
2. 「状態を更新」で保存済みtaskの状態を確認する。応答が不明な場合は自動再送せず、Tripo側と保存済みtaskを確認する。
3. 成功後に「生成済みGLBを取得」を押す。アプリはHTTPSでGLBを取得し、GLB形式・512MB以下・SHA-256を検証して、作品の3D素材フォルダへ保存する。
4. 起動中の同じBlender GUIへ接続した状態で「同じBlender GUIへ取り込む」を押す。対象のfile/scene/view layerと観測版を再確認してから、検証済みGLBだけをBlender標準インポータで読み込む。別のBlenderや別作品へ自動接続しません。
5. 取り込み後は同じGUIの状態を再観測し、必要ならMacのCodexまたは人へ制御を渡してモデル・リグ・カメラを調整し、既存の複数アングル撮影へ進みます。

この連携はTripoの利用料金・生成品質・利用規約を自動判定しません。APIキーと生成対象を確認できる専用キーを使い、実モデルの形状・テクスチャ・ライセンスを目視確認してください。固定版は image_to_model / v2.5-20250123 の1枚画像経路です。複数画像入力や生成品質の受入は別途実地確認します。

### 人物レイヤーの局所色変更（実推論未検証）
