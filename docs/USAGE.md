# 使い方

初回だけ[導入・接続](INSTALL_MAC.md)を済ませます。画面は「原稿」「コマ割り編集」「作画」「仕上げ」の順に進み、完成品は上部の「書き出す」から保存します。動画は必要なコマに追加できます。空の作品は「原稿」、保存済み作品は「作画」で開きます。

## 小説から漫画にする

| 工程 | 操作と完了の目安 |
| --- | --- |
| 執筆 | 原稿リポジトリで本文・設定・人物参照を整える。文章の修正は原稿側で行う |
| 原稿 | 原稿ライブラリで作品・ブランチ・取込対象の話を選び、差分を確認して取り込む |
| ネーム | GitHubのネームを読み込むか、選択原稿から候補を作り、枠と掲載方針を確認して採用する |
| 作画 | 確定したネームの単コマ・選択コマ・不足分を生成し、更新案を適用する |
| 仕上げ | ページ上で画像配置・文字・解像度を確認し、セクションの完了を承認する |
| 出力 | PNG / CBZ / Live Mangaを選ぶ。制作途中なら非公開プレビューへ転送できる |

アプリは原稿に書き戻しません。原稿は同一commitの本文・設定・参照画像をまとめて保存し、更新後も旧漫画が使う原稿版を残します。生成・編集の候補と採用版は分かれており、採用後もUndoできます。

## 1. 原稿を取り込む・更新する

1. 「原稿ライブラリ」で原稿ブランチのdev / mainを選び、「一覧を更新」します。
2. 作品・話・シーンを選びます。閲覧する話と、取込対象の話は別に選べます。
3. 「原稿の更新を確認」で本文・設定・人物参照の差分を確認し、「取り込む」で反映します。

確認は手動です。起動時の自動取得・自動適用はありません。取得失敗では現在の漫画を変更せず、未取込み候補は終了時に消えます。取得済みの他の話も更新対象に保持します。

別作品への切替は保存後の再起動を伴います。作品ごとに画像・履歴・Job・SQLiteを分離します。再起動後はGitHubトークンとAPI接続を必要に応じて再登録してください。原稿形式は[設計§4.1](IMPLEMENTATION_PLAN.md#41-正本と参照)を参照します。

「原稿と漫画への反映状態」で未反映・反映済み・変更・削除された文章を確認できます。段落をクリックして制作範囲を選び、タグの「いずれか／すべて」で場面を絞れます。変更のない反映済み段落も明示的に再計画できます。検索や選択だけでは再生成しません。

## 2. ネームを確定して作画する

チャットAIで作ったネームは「制作する場面・保存した原稿 → 同じGitHub版のネームを読み込む」から受け取れます。取り込んだ原稿と同じ版から候補を取得し、掲載方針・実文字入りプレビューを確認して採用します。「このネームで制作」で確定した配置を保って作画し、完成後は該当ページの仕上げへ進みます。手動JSONも同じ候補経路です。詳細は[ネームの受渡し](NAME_PLAN_IMPORT.md)を参照してください。

アプリで選択原稿から更新案を作る場合:

選んだ範囲の更新案を作り、原文入りネーム候補を確認します。原文の割当を前後のコマへ移し、分割・統合や枠の調整を行って「このネームを確定」。その後、単コマ・選択コマ・不足分だけを作画し、更新案を適用します。仮表示の原文は画像に焼き込みません。

割当を変更すると対象の候補コマだけが作画待ちに戻り、旧採用画像は残ります。ネーム確定後の作画・再開では枠を作り直しません。原稿や参照が変わって基準が古くなった候補は、確認し直してから適用してください。

「漫画にする」は選択した制作範囲の初稿を順に作り、成功後は「仕上げ」へ進みます。途中で止まった場合は保存済み画像を使って続行でき、文字配置だけの失敗で画像を再生成しません。「制作する場面・保存した原稿」から別の初稿を作り、旧稿に戻ることもできます。

コマを選び「前後のコマ・人物参照」を開くと、ページをまたいだ隣のコマと見比べられます。未作画や別場面を区別し、衣装・持ち物・視線を確認してください。修正候補は作成時の元画像と並べて表示されます。作成後に採用画像が変わった場合は、現在の画像も別に表示します。

処理中に独立した原稿範囲を追加できます。共有コマや配置に依存する範囲は待機します。外部LLMの計画は設定で最大2件、ローカル推論は1件ずつ。個別停止・全停止後も完成素材と候補は残ります。

### 作画先を選ぶ

画像モデルはローカルFLUXまたはRunway静止画を選びます。外部LLMの選択とは別設定です。モデルは勝手にダウンロードされず、ローカルモデルは使うものだけ明示準備します。クラウドは送信許可・キー・作品の費用上限が必要です。

対応寸法・操作・参照枚数は選択モデルの表示に従ってください。非対応の入力を別モデルへ自動転送しません。人物参照を送ることと、出力の人物同一性が保たれることは別です。実際の絵を確認して採用します。

## 3. コマと文字を整える

| 直したいもの | 操作 |
| --- | --- |
| 枠・配置 | 「コマ割り編集」で四隅をドラッグ。内部は全体移動、Escで取消。枠専用Undo / Redoが使える |
| コマ数 | テンプレートで1〜16枠に変更し、対象のページ区間を再配置する。ページを外しても原文・画像は保持する |
| 画像位置・倍率 | 「画像トリミング」で調整。「画像全体を枠内に収める」で全体表示へ戻せる |
| 文字 | 吹き出し・ナレーション・枠なしテキストの位置、サイズ、しっぽ、余白、固定を編集する |
| 表情などの一部 | コマ画像で矩形を指定し、自然言語の修正指示を実行。範囲外のRGBA画素を保持する |
| 自然言語の配置修正 | 「3コマ目の文字を左へ」などと入力し、対象・変更値を確認して適用する |

通常の配置編集は表示ページが対象です。AIも選択範囲だけを変更し、「全ページを対象」を選んだ時だけ全体を再計画します。枠数テンプレートは表示ページから指定したページ数だけを詰め直し、容量不足ならその区間にページを追加します。前後のページと原文・作画は保持します。ページの確定・解除操作は不要です。

枠破りは画像のはみ出しを隣コマへ重ねる機能で、人物の自動切抜きではありません。隣コマの文字との重なり、未割当、読書順の警告を解消してから出力してください。

自然言語の軽量編集はUndo / Redoできます。保存した編集候補は再起動後も比較・採用できます。再作画は候補として残り、同じコマの連続生成は先の候補を採用してから指示します。画像による対象認識には、接続設定で画像送信を許可した対応LLMが必要です。認識矩形を確認してから部分修正へ進めます。

AIコマ割りの保存候補は、対象ページの「演出AIでこのページを配置」に戻ります。複数あるときはページと案の内容で選び、採用または破棄してください。破棄した案は再起動後も表示されません。作品を変更して古くなった案は採用できません。

英語版は「作品言語」→English→「英訳を作る」。原文の段落IDに対応した派生訳を文字層と動画字幕で共有し、原文・作画を変更しません。

## 4. 仕上げて完成にする

「仕上げ」で出力と同じページを確認します。文字あふれは省略せずエラーになるため、文字枠・コマ割りを調整してください。

「書き出す」の「出力前に修正」から、不備のあるページ・コマへ直接移れます。未作画は作画へ、台詞の欠落や作画更新後の文字配置は仕上げへ進みます。PNGは表示中のページだけを検査するため、別ページが制作中でも出力できます。

文字枠ごとに「文字方向」で横書き／縦書き、「書体」でゴシック／明朝を選び、適用します。縦書きは上から下、列は右から左へ進みます。英数字は1文字ずつ縦に並び、ルビ・縦中横には未対応です。ネームv2の文字編集も実際の枠の縦横比と文字サイズで表示します。書体はMacにあるフォントを使います。

画像の解像度診断はページ寸法とトリミング倍率から必要画素数を算出します。足りていれば再生成は不要です。

- **補間拡大**：2倍／4倍の候補を作ります。最大4096px・1600万画素。失われた細部を復元するAI超解像ではありません。
- **配置に合わせた仕上げ**：元画像・人物・画風参照から候補を再生成します。縦横比、枠、位置、文字は保持しますが、描線や構図の一致は保証しません。対応モデル・寸法の範囲内で使います。

候補は現在のページで比較して採用します。候補作成後に元画像・参照・配置が変わった場合は採用できません。途中終了は「保存済み仕上げを回収する」で確認します。

セクションを確認し「このセクションの漫画化を完了」を押すと、本文・参照・採用作画・文字・枠の版を承認します。後の変更で「要確認」になった部分を再確認してください。「次の未完了セクション」で続行でき、完了解除・承認のUndoも可能です。完了操作だけで外部送信・公開はしません。

## 5. 書き出す・プレビューを送る

「書き出す」から形式を選びます。PNG / CBZ / MP4は `ダウンロード/Manga Mac`、Live Mangaは `ダウンロード/live-manga-<releaseId>` へ保存し、既存ファイルを上書きしません。

PNG／CBZの幅は800・1600（標準）・3200pxから選べます。ページ比率と配置を維持し、文字と枠は出力解像度で描画します。選択は起動中だけ保持し、Live Mangaは従来の1600×2260pxです。「画像解像度を確認」から不足するコマの仕上げへ移動できます。補間拡大で細部が増えるわけではありません。画像寸法を読めない場合も確認対象になります。

| 形式 | 用途 |
| --- | --- |
| PNG / CBZ | 静止漫画。ページ上で確認した枠・トリミング・文字を反映 |
| MP4 | 動画画面で採用した単独ショット |
| Live Manga | コマに動画を割り当てた配信用フォルダ。対応するlive-mangaへ渡す |
| 非公開プレビュー転送 | 保存済みの話全体を別端末で確認。途中稿も送れる |

Live Mangaでは静止画と同じ枠・配置を使い、コマ内動画はホーム枠でマスクします。書き出しにはffprobeが必要です。公開物に生成元DB・資格情報・参照原本・未採用素材・blendを含めません。刊行フォルダは編集用バックアップではありません。

非公開転送は、話全体の保存済みページが対象です。タグ検索は転送範囲を変えません。未作画・文字待ちは途中稿として表示し、ページ未配置のコマは件数を示して除外します。転送中も制作できます。失敗時は同じ転送版の「不足分から再開」を使い、他端末と競合したら転送先の現在版を確認します。接続と認証は[初回設定](INSTALL_MAC.md#live-mangaの配信用書き出し)を参照してください。

## 必要なコマに動画を付ける

1. 漫画でコマを選び「このコマを動かす」から動き・寸法・尺を保存し、作画を開始画像として動画を準備します。漫画がなくても動画画面で原作と固定撮影画像からショットを作れます。
2. 「動画API接続」でモデル・キー・送信内容・作品の累計予約上限を確認します。動きの指示は直接入力するか演出LLMで案を作り、保存します。
3. 生成し、状態照会→取得→再生確認→候補採用へ進みます。採用後に漫画のコマへ割り当てます。割当だけではAPIを呼びません。

複数コマでは共通の動き・尺・寸法が、個別変更していないコマへすぐに反映されます。個別変更は保持され、「共通設定に戻す」で解除できます。計画を保存し、バッチの件数・モデル・費用を確認して順に送信します。編集中の計画は保存するまで生成できません。停止後も送信済みtaskと完成素材は残ります。新規送信と既存taskの照会・回収を分けて扱います。

Runway Gen-4.5 / Gen-4 Turbo / Seedance 2.5に対応します。尺・比率・料金はモデルごとに異なるため画面の見積もりを確認してください。隣接コマのA→Bには終端画像対応モデルが必要です。モデル切替時に不適合な尺・終端画像などを勝手に変更しません。

再起動後は同じRunwayキーを再登録して保存済みtaskを照会します。task IDがない要求は自動再送しません。取消・削除で完了済みtaskが消える場合もあるため確認表示を読んでください。漫画の履歴と動画の採用・Undoは独立し、ショットの新採用版へコマの割当を自動置換しません。

## Blenderで構図を作る

Blenderは任意です。[接続を準備](INSTALL_MAC.md#アプリからblenderを開く197)し、対象コマで「このコマのBlenderを開く」を選びます。通常は同じGUIで撮影・編集し、別のBlenderを裏で起動しません。

演出は「勇の肩越しから」などの自然言語で指示できます。既存素材・対応ポーズ・カメラ・照明を操作し、不足素材や未対応リグを別人物で代用しません。AIの完了通知だけで採用せず、画像を確認します。

| 次の作業 | 操作 |
| --- | --- |
| 手で直す | 「手動へ渡す」。編集終了後に操作権を戻して再観測 |
| Codexに頼む | 「MacのCodexへ渡す」で制作依頼ZIPを保存し、同じGUIを引き継ぐ |
| 複数構図を比べる | 「同じシーンのアングル候補を作る」で注視対象・角度を選ぶ |
| 撮影を残す | 「新しい候補版へ保存」して比較・採用 |
| AIを通さず整える | 撮影原本をCompositorへ渡す |

角度候補は同じScene・frameから撮り、カメラを元に戻します。途中停止・引継ぎ後も完成候補は残ります。作業ファイルの保存と、固定撮影候補の保存は別操作です。アプリのUndoは採用版を戻し、Blenderの手動操作は巻き戻しません。

Web素材は直接HTTPS URL・出典・ライセンスを指定し、Blenderの標準取込みで読みます。Tripoを使う場合は、参照送信・費用上限を確認して生成→状態照会→GLB取得→同じGUIへ取込みます。いずれも元素材・採用済みcheckpointを上書きしません。

## レイヤーで直す

[Compositor連携版](INSTALL_MAC.md#compositor連携版開発中217)を導入し、コマの「外部レイヤー編集」から接続します。手動またはCodexへ渡し、アプリへ操作権を戻して再観測→候補保存→採用の順に進みます。

- **分解**：「原画をレイヤーに分解」で専用モデルを明示準備し、2〜6層へ分けます。原画を残し、順序・透過・人物対応を確認します。対応外の寸法を自動変換しません。
- **移動**：確認済みの人物レイヤーに「人物名を少し左へ」などと指示できます。一意な人物対応が必要です。移動には画像生成・分類LLMを使いません。
- **局所色変更**：対象レイヤー・人物・矩形・色を確認して生成します。元alphaと範囲外画素を保持し、結果も候補保存・採用が必要です。向き・ポーズ変更には使えません。

手動編集で版が変わった結果は保留し、現在のドキュメントへ自動取込みしません。応答不明なら「未確定の結果を照合」、保存後の中断なら「保存済み候補を回収」を使います。実推論の分解精度・人物同一性・24GB性能は別途受入が必要です。

## 保存・復旧

作品は自動保存されます。APIキー・トークンは作品に保存しません。バックアップと更新前の保全は[初回設定](INSTALL_MAC.md#更新バックアップ)を参照してください。

画像生成後に終了した場合は「保存済み作画を回収する」を使います。未確定の要求を再送せず、保存結果を候補へ戻して確認・採用します。欠損・破損・未完了などで回収できない場合は理由を表示します。Blender・動画・Compositorも保存済み結果を照合してから再開してください。

実Macの画質・速度・ピークメモリ・外部API・復元の確認範囲は[検証記録](VALIDATION.md)。画面テストや人工画像の成功だけを実機品質の合格とは扱いません。
