# Manga Mac — ローカル漫画制作アプリ

完成脚本をGitHubのmainから読み取り専用で取得し、原文を保持した演出計画、参照付き作画、領域編集、ページ出力を行うTauri 2 + React + Rust + Swiftアプリです。

**現在は初期実装・実機検証前です。完成版ではありません。** LinuxでWebビルドとドメインテストを実行済み。Apple Silicon上の推論品質、メモリ使用量、オフライン動作、配布物のクリーンインストールは未検証です。

## 設計の正本

**[設計・実装計画 v4.0](docs/IMPLEMENTATION_PLAN.md)** を今後の実装の正本とします。既存の2D制作を保持しながら、**Blenderで舞台・人物・カメラを扱う → 撮影する → 画像AIで漫画化・部分修正する → アプリでページにする**構成へ拡張します。

3D素材管理・ポーズ・配置・描画はBlenderの既存機能をAPI/MCP経由で呼び出し、独自の素材台帳・3D編集エンジン・3Dビューワーを再実装しません。設計書には責務分担、システム図、4コマ1ページの作業・データフロー、保存版、修正範囲、費用、移行・受入条件をまとめています。

mainにはBlender接続・撮影・組版と動画制作の実装候補が追加されています。実Blender、Mac、動画APIの受入は未完了です。Tripo連携・外部画像生成APIは未実装です。現行版の使い方と制約は本README、目標仕様は設計書で管理します。外部に配布した旧設計資料と異なる場合は、本リポジトリのmainにある設計書を優先します。

## Mac購入後のインストール

**[インストール・初回設定ガイド](docs/INSTALL_MAC.md)** に、DMGの取得からAPI/Ollama設定、原作接続、初回制作、更新まで記載しています。Macビルドが成功しDMGが作られた後に使う手順です。

## 使い方

1. `main`へのマージ後にGitHub Actionsの `Check and build Mac app` が実行されます。`macOS release package` が成功した実行から `Manga-Mac-Apple-Silicon-unsigned` を取得します。これはmacOS 14以降のApple Silicon向けです。`dev`の `macOS validation` が作る成果物は統合後の検証用で、配布には`main`の成果物を使います。ビルド失敗中はDMGは存在しません。
2. DMG内のManga Mac.appをApplicationsへコピーします。初期ビルドは署名・公証されていません。
3. LLMの接続先を設定します。外部APIならモデルIDとAPIキーを入力。ローカルならOllamaを別途インストールし、使うモデルを取得します。
4. 「接続・人物設定」で原作リポジトリ（`owner/repository`）、話ID、必要ならContents: readのみのfine-grained tokenを指定します。トークンはメモリのみ保持しSQLiteやログへ保存しません。
5. 更新を確認し「この版を取り込む」。原稿で宣言された人物参照画像は、本文・設定と同じcommitから自動登録されます。原作にない人物参照は必要に応じて手動登録します。
6. 「画像モデルを準備する」でFLUX.2 klein 4Bのモデルを取得します。ダウンロード容量・処理時間は環境に依存します。
7. 制作方法を選び「漫画にする」。標準のBlender経路は、準備済みの舞台からコマごとの演出・撮影・漫画化へ進みます。「画像AIで直接作画」は従来の2D経路です。保存済み画像は再生成せず再開できます。
8. 部分修正はコマ画像をドラッグして範囲を指定し、自然言語の指示を入力して「修正する」を押します。顔推定AIは使用しません。範囲外のRGBA画素は元画像を保持します。
9. 「作品言語」で日本語（原文）／Englishを選びます。Englishは「英訳を作る」で、原文段落IDに対応する派生版を作成します。原作本文と作画画像は変更せず、同じ英訳を漫画文字層と動画字幕で共有します。
10. 人物・原作整合を確認し、PNG/CBZへ出力します。Macでは「ダウンロード/Manga Mac」に日時付きファイル名で保存し、既存ファイルを上書きしません。文字が入り切らない場合は省略せずエラーにします。

## 動画1ショット（実装候補・有料実API未検証）

「動画」へ切り替え、既存原作とPNGの作画/固定撮影画像からショットを保存します。開始画像と同じ縦横比の出力を選びます。動きの指示は直接入力するか、登録済みの演出LLMで案を作ってから保存します。原文・人物IDは変更しません。

動画API接続は初期無効。Runway gen4.5のキー・送信許可・作品の累計予約上限を設定した後、5秒の生成要求を送れます。状態照会は手動で5秒以上間隔をあけます。成功後に動画を取得・検証し、再生→候補採用→MP4出力へ進みます。動画の採用/Undoは漫画の履歴に影響しません。

再起動後は同じRunwayアカウントのキーを再登録し、保存したtaskを照会します。task ID未受領の要求は自動再送しません。取消APIは完了済みtaskを削除するため、その影響を確認した場合のみ実行します。キーと署名URLは作品へ保存しません。料金・固定CDN・入力制限・未検証項目は正本§12と[検証記録](docs/VALIDATION.md)を参照してください。

## 実装した境界

### 共通原稿形式 `story-source/v1`（#143）

新しい原稿の形式正本を `contracts/story-source/` に追加しました。原稿リポジトリでは `source/manifest.json` を入口とし、`episodes[].scenes[]` の配列順で `P1-3` のような現在位置を作り、各場面の固定 `id` で同一場面を継続識別します。本文は `manuscript/p01/p01-03.md`、設定は `settings/*.md`、人物基準画像を使う場合は `assets/` に置きます。

`validate.mjs` はmanifest、連番パス、ID、タグ、本文の先頭見出し、宣言ファイルの過不足を機械検査します。`structure.mjs` は話・場面の追加・移動・削除・再採番を計画し、固定IDを変えずにファイル移動を行える対応表を返します。本文の生成・AIによる補正・原稿への書き戻しは行いません。

この共通契約を原稿側・静的reader・manga-macの同期入口で共有します。manga-macはstory-source/v1を新規原稿の単一正本として読み取り、既存schema 1/4は旧作品を保つための互換adapterとして扱います。

原稿の意味タグは、story-source/v1 manifestのsceneに `"tags": ["図書館", "雨"]` のように記載します。タグなしは省略可能です。原稿側で編集後、アプリの「GitHub側の更新を確認」から手動で取り込んでください。原稿画面で「いずれか／すべて」の条件検索と該当シーンの一括選択ができます。関連する差分が別シーンへ広がる場合は追加対象を確認します。選択後の反映は既存の漫画化処理を使い、タグ検索だけで再生成や転送は行いません。

- story-source/v1は入れ子の`episodes[].scenes[]`の順で本文を取得し、`settings[]`、`characters[]`の固定ID・宣言画像を同一commitから読み込みます。manifestの形式・ID・canonical path・タグ・見出しを共通validatorで検査し、作品名による実装分岐はありません。
- 既存schema 1/4は`episodes[].scene_ids`の順で宣言された本文パスを読む互換adapterです。schema 4で構造化人物宣言がない場合だけ、旧Markdown captionを互換取得します。
- protocol版と実取得commit・manifest SHA-256・日時をsnapshotへ記録します。アプリに作品別の確認基準commitは同梱しません。
- 人物画像は構造化宣言を優先し、schema 4のみ旧Markdown captionからの互換取得を行います。実形式・20MB上限・SHA-256を確認し、明示取込み時だけ人物正本へ反映します。
- mainのSHAを一度取得し、全ファイルを同じ40桁SHAで取得。同期取得失敗は現行スナップショットに影響しません。新版取得と適用は別操作。更新確認は手動ボタンだけで行い、起動時・定期の自動確認はありません。
- 原文の段落IDをLLMへ渡し、全IDの順序・一意性・完全性を検証。表示原文はスナップショットから直接取得。AI出力で台詞を上書きしません。
- キャラの画像バイト列をSHA256で記録し、Rustでも照合してからSwiftのmoodboard入力へ渡します。入力順、人物ID、ハッシュ、モデル、seed、寸法、ステップ数をコマに記録します。見た目の一致は保証しません。
- 画像生成は専用プロセスのMediaGenerationKit `.local` のみ。処理完了後プロセスが終了しモデルメモリを解放。Ollamaはkeep_alive: 0。
- 同時画像ジョブは1つ。要求にjob ID・原作版・対象・基準版を保持。変更済み入力への古い結果や停止後の結果は候補にとどめます。再起動時の実行中要求は応答未確定として保留し、無断再試行しません。
- 編集履歴は保存済み画像を保持。選択外のコマは変更せず、undoは再推論しません。
- SQLite WALで作品を保存。画像はSHA-256付き不変ファイルへ分離し、検証・同期後にDB参照を更新。旧JSONは移行前にバックアップを保持。スキーマv2でも旧2Dコマは撮影版なしで開けます。

## ブランチ運用

- `main`: 配布・本番相当の正本。マージ後は`macOS release package`で配布用DMGだけを生成する。
- `dev`: 通常開発の統合先。変更領域に対応するLinuxチェックだけを実行し、共通Rust・依存関係・未知の変更では全系統を実行する。native/Tauri変更をマージした後だけ`macOS validation`（Swift/Tauri arm64ビルド、Rust回帰試験、検証用DMG）を実行する。
- `feature/*`・`fix/*`・`docs/*`: `dev`から作り、原則として`dev`宛てのPRにする。
- `dev → main`: `dev`でのMac検証が成功したまとまりだけをPRで昇格させる。PRでは共通Linuxチェックを確認し、mainマージ後の配布用DMG生成とは分けて扱う。
- `hotfix/* → main`: 重大不具合だけの例外。main固有の修正は必要に応じて別PRで`dev`にも反映し、履歴を合わせるだけの`main → dev`マージは行わない。

`macOS validation`が失敗したコミットは`main`へ昇格させず、原因を修正して`dev`へ反映する。`main`と`dev`へ直接pushせず、PRを経由する。原作同期機能が読む原稿repositoryの`main`と、本アプリの開発用`dev`を混同しない。

## 開発

```sh
npm ci
npm test
npm run build
npm run dev
```

ブラウザでは空作品のサンプル表示と組版画面を確認できます。GitHub認証・推論はRust IPCを通すためMacアプリ限定です。ブラウザからクラウドAIへ送信しません。

macOS開発環境での起動:

```sh
swift build -c release --package-path helper
mkdir -p src-tauri/binaries
cp helper/.build/release/manga-engine src-tauri/binaries/manga-engine-aarch64-apple-darwin
npm run tauri dev
```

GitHub Actionsでは、変更領域に対応するLinuxチェックだけを実行します。UIブラウザ試験、実Live連携、実Blenderレンダリング、依存監査は該当変更だけで実行し、共通Rust・依存関係・未知の変更では全系統を実行します。native/Tauri変更を`dev`へマージした後はMac固有のビルド・回帰試験・検証用DMG、`main`へアプリ変更をマージした後は配布用DMGを生成します。ドキュメントのみと検証済み昇格は分類だけで通します。Actionsの成功は、実機での生成品質・視覚・性能受入試験の代替にはなりません。

## 実機受入試験

1. 2人の正本を登録し、2人が登場するコマで両方の参照ID/ハッシュを確認する。
2. 一人の顔領域を選び表情を変更。保存PNGをRGBA比較してマスク外差分ゼロを確認する。
3. 再起動し、履歴・参照・原作SHA・失敗ジョブを確認する。
4. 元に戻す操作で旧画像が厳密一致することを確認する。
5. モデル導入後にネットを遮断して、Ollamaを選んだ状態で取得済み原作の生成・編集・保存・出力を試す。
6. 二人の顔/衣装の混線、生成速度、ピークメモリを記録する。合格前に参照品質の数値を宣言しない。

## LLMの接続先を選ぶ

「接続・人物設定」→「AIの接続」で、演出・コマ計画とBlender自動演出に使う接続先を選べます。顔推定用の別接続は不要です。

| 接続先 | 方式 |
|---|---|
| Ollama | ローカル `/api/chat`（初期値） |
| OpenAI | Chat Completions |
| Google Gemini | OpenAI互換API |
| Anthropic Claude | Messages API |
| DeepSeek | OpenAI互換API |
| OpenAI互換API | 自分のHTTPSベースURLを指定 |

外部APIは利用可能なモデルIDとAPIキーを入力し、「接続をテスト」でJSON応答を確認します。接続テストはテキストだけの少量リクエストであり、画像入力対応まで保証しません。互換APIがJSONモードを受け付けない場合は設定をオフにできます。返されたJSONと原文IDは引き続き検証します。

- 演出用APIには脚本・設定・人物の説明を送信。Blender自動演出では利用可能な素材名・構図・操作結果も送信します。画面に送信先を表示します。
- 画像作画そのものは引き続きMac内のFLUXです。外部LLMを選んでもWebサービス型アプリにはなりません。
- APIキーとLLM接続設定は起動中だけ保持し、作品SQLite・バックアップ・生成履歴へ保存しません。接続先を切り替えるとキーはクリアされます。
- 自動フォールバック、自動リトライはありません。別事業者に無断で原稿を送りません。
- 外部APIはHTTPSのみ。リダイレクトは追従せず、HTTPエラー本文（原稿や認証情報を含み得るもの）は表示・保存しません。
- 外部API利用料は利用者のAPIアカウントへ発生します。外部APIを選んだ処理はオンライン接続が必要です。

接続アダプタはモック応答によるテスト済み。実APIキーを使った課金リクエストとMac実機通信は未検証です。

API仕様: [Gemini互換API](https://ai.google.dev/gemini-api/docs/openai)、[Claude Messages](https://platform.claude.com/docs/en/api/overview)、[DeepSeek](https://api-docs.deepseek.com/)。

## 初稿と自然言語・手動編集（段階実装）

「漫画にする」からページ配置・作画・文字配置を順に実行し、書き出しと同じ初稿を表示します。文字配置が失敗しても完成画像を再生成せず再開します。採用済み作画を含む原作改訂場面は自動上書きしません。

表示ページに「3コマ目の文字を左へ」のように入力すると、選択済み演出LLMが既存の文字/枠/crop操作を提案します。対象と変更値を確認して適用するか、軽量編集の自動適用を選べます。Undo/Redo可能です。Blender演出と指定済み領域の描き直しは既存経路へ接続し、再作画を候補として保持します。

解像度診断、補間拡大・仕上げ候補、動画準備・既存動画割当も自然言語入口から既存処理を呼びます。新規有料動画生成は既存動画画面の許可・予算設定を通します。

文字枠は吹き出し・ナレーション枠・枠なしテキストとして、ドラッグ、右下ハンドル、しっぽ先端、数値で編集できます。ナレーション枠もコマ内の任意位置へ置け、下部固定ではありません。形状・文字サイズ・行間・余白・固定を保存します。画像生成は呼びません。任意のJev判断は「接続・人物設定」で送信用途を許可して登録できます。未設定なら選択済み演出LLMを使います。

制作する場面を選択でき、原作更新時は旧稿を残して別初稿を作れます。「保存した原稿」から戻せます。自然言語の候補も再起動後に比較・採用できます。

接続設定で作画送信を有効にすると、画像対応LLMが対象矩形を提案します。認識範囲を確認して部分修正へ進めます。文字回避では認識領域との重なりを検査します。軽量編集→生成の複合指示に対応し、途中失敗は保存済み操作数を表示します。同じコマの連続生成は先の候補を採用してから指示してください。Jev実APIの日本語判断品質、Mac GUI/24GB実機品質は未検証です。各Issue全体の完了を意味しません。

## AIによるBlender演出（Issue #46）

初回は演出AIの接続と、Blenderの素材フォルダ・舞台blendを準備します。通常制作ではScene/Camera/frameを入力せず「漫画にする」で進めます。コマを選び、修正欄へ「勇の肩越しから」「もう少し寄って」などを書いて「Blenderで演出して漫画化」を押すと、対象だけ撮影し直し、旧作画を残して候補を作ります。

対応範囲は既存素材の取込、静止した親なしObjectの配置、登録済みポーズ、カメラ位置・方向・焦点距離、既存照明です。視線は対応するポーズ素材を必要とします。不足素材・複雑なリグは理由を示して止まり、別人物で代用しません。Blenderのモデル・リグをアプリで新規生成する機能ではありません。

演出AIは操作ごとにBlenderの実状態を読み返します。自動の視覚品質判定は行わず、出来上がりは利用者が確認します。1コマ12操作を上限とし、停止後は「演出を再開」で保存結果を照合します。未確定要求は「詳細調整・Blenderの保存結果を確認」で解決し、再送しません。新しい指示に変える場合は前の演出を取り下げます。取り下げはBlenderの変更を巻き戻す操作ではなく、旧撮影・採用作画は残ります。

### Webの既存3D素材を取り込む

「接続・人物設定 → Blenderで撮影する → Webの既存3D素材を取り込む」から、配布元で取得した直接HTTPS URLを指定できます。対応形式は `.blend`、GLB/glTF、FBX、OBJ、ZIPです。URLに拡張子がない場合は保存名を指定します。配布ページとライセンス表記を入力し、Blenderで検出したモデル／Object／Collection／Actionを選んで取り込みます。

取得は512MB、ZIP展開は1GB・4096ファイル、候補は200件を上限とします。ローカル／プライベートIP、認証情報入りURL、パス逸脱、シンボリックリンク、異常な圧縮率を拒否します。任意Pythonや同梱アドオンは実行せず、固定Blender 4.5.13の標準import／appendを呼びます。取込後は出典URL・配布ページ・ライセンス・取得SHA-256をBlender datablockに保存し、依存を既存packingでcheckpointへ固定します。素材の利用可否やライセンス自体をアプリが保証する機能ではありません。

### 自由なコマ割り

「コマ割り編集」で枠を選ぶと四隅を個別にドラッグできます。枠の内部は全体移動、Escは取消です。枠専用Undo／Redoがあり、作画は再生成しません。

枠を選んで「枠破り」を押すと、まず従来どおりコマを描いたまま、ホーム枠の外へ出る作画だけが隣コマの上に乗ります。破線はそのはみ出し範囲です。人物の切り抜きはしません。アルファ付き画像はそのまま合成します。隣コマの文字と重なるはみ出しは完成出力を拒否します。Live Manga のコマ clip はホーム枠のまま、artRect はページ作画と同じ全面表示です。コマ動画の再生はビューワーがこの clip でマスクします。

枠数を選んでテンプレートを適用すると1〜16枠へ変更できます。6枠を作り、枠を選んで「選択枠のコマ」から既存コマを割り当ててください。4コマ／6コマページを混在できます。減らした枠の本文・画像は未割当で保持されます。未割当・重なり・読書順の警告を解消してからPNG／CBZへ出力してください。

「演出AIでこのページを配置」では自然言語で候補を作成し、プレビュー後に採用できます。「全ページを対象」はページ分割も変更します。既存の演出AI接続を使います。形状は凸四角形限定です。実モデル品質・Mac実機の操作評価は別途検証が必要です。

### 画像トリミング

「コマ割り編集 → 画像トリミング」で枠を選ぶと、既定の全面表示（コマ形状でマスク）のまま位置と拡大率を変えられます。Escでドラッグ取消、枠のUndo/Redoで配置を戻せます。「画像全体を枠内に収める」は従来の contain 表示です。「枠を編集」で四隅操作に戻ります。

元画像・セリフ・吹き出しは変更しません。通常の作画画面は原本表示です。仕上がりはコマ割り画面または「書き出しと同じページを確認」で確認してください。PNG/CBZに同じ配置が反映されます。旧作品も設定がなければ全面表示になります。Live Manga v2への書き出しにも同じトリミングを反映します。高解像度化は別途[Issue #57](https://github.com/kdob1042/manga-mac/issues/57)で扱います。

### 配置確定後の画像解像度

通常の作画画面でコマを選び、「画像の高解像度化」から2倍／4倍のローカル補間拡大候補を作れます。現在の1600×2260ページとトリミング倍率に対する必要倍率を表示します。最大4096px・1600万画素。AI超解像ではなく、画素数を増やす処理で、失われた細部は復元しません。

候補を比較して採用するとPNG/CBZにも反映。元画像は不変の作画履歴に残り、通常の「元に戻す」で復元できます。配置と文字は変更せず、候補作成後に配置が変わると採用を拒否します。途中終了時は自動再実行せず、要求を取り下げてから再作成してください。これは補助機能で、AIによる再生成とは別です。

### 配置に合わせた再生成・仕上げ（#57）

先に「画像トリミング」で表示位置と拡大率を決め、通常の作画画面でコマを選んで「配置に合わせた仕上げ」を開きます。必要な原画像サイズと現在の画素数を表示します。画素数が足りればそのまま出力でき、縮小用の画像作り直しは不要です。必要な場合だけ「元画像を参照して仕上げ候補を作る」で、既存のローカルFLUXへ元画像・人物・画風参照を渡します。

候補を現在のページ配置で比較し、確認して採用してください。構図・人物・描線の一致は保証されません。元画像は不変履歴に残り、コマ枠・画像位置・拡大率・セリフ・吹き出しは変更しません。出力画像の縦横比は元画像と厳密に一致させます。途中終了時は「保存済み仕上げを回収する」で再生成せず候補へ戻せます。元画像・配置・参照が変わった候補は採用できません。

現エンジンは256〜1024px・64px刻みです。対応できない縦横比は明示エラー、必要サイズが上限を超える場合は不足警告を表示します。上限内で再生成しても不足を解消したとは扱いません。専用超解像モデル・追加モデル取得・外部APIは使いません。Mac実機での生成品質・24GB性能と1024px超の生成は未検証／未対応です。

### コマを押すと動く作品を書き出す（Live Manga）

1. 漫画でコマを選び「このコマを動かす」に動きと寸法を入力し、「この作画から動画を準備」。コマ限定の原文範囲・人物・採用作画を既存動画画面へ渡す。
2. 既存の接続・許可・予算設定で動画を生成・確認・採用。漫画へ戻り、その動画を「割り当てる」。割当だけではAPIを呼ばない。
3. 「Live Mangaを書き出す」でDownloadsへ不変の刊行フォルダを作る。自由四角形、ページごとのコマ数、画像トリミングをv2契約で保持する。clip はホーム枠、artRect は静止画と同じ cover 配置。作画や原文との不整合は、動画変更または割当解除が必要。ショット側の新採用版へ自動置換しない。コマ内再生と拡大表示は live-manga ビューワー側です。
4. フォルダをlive-mangaの刊行CLIへ渡す。生成元DB、資格情報、参照原本、未採用素材、Blenderファイルを公開物に含めない。

書き出しにはFFmpegの`ffprobe`が必要（Macでは `/opt/homebrew/bin/ffprobe` / `/usr/local/bin/ffprobe` またはPATH）。`brew install ffmpeg`で導入後、再試行できる。自動再エンコードはせず、H.264・無音・対応比率だけを公開する。

対応契約・固定commitは `vendor/live-manga/lock.json`。`node scripts/sync-live-contract.mjs`で整合チェック。元のPNG/CBZ/単独動画出力は継続する。

### 複数作品の切替

左側の「原稿ライブラリ → 一覧を更新」で接続先の`library.json`を一度取得し、「作品→話→シーン」を選びます。catalog・manifest・本文・設定・人物基準画像は同じ取得commitに固定し、更新確認と制作への適用は別操作です。選択した作品は`workId`と作品rootを保持し、同じGitHub repo内でも画像・履歴・ジョブ・SQLiteを作品ごとに分離します。切替は保存後の再起動を伴います。トークンは起動中のみ保持するため再入力してください。旧単一作品repoの接続も維持し、**story-source/v1とinvestor-life-source/v1、manifest schema 1/4をread adapterとして読み取ります。**

### ページの編集範囲

ページ確定の操作は廃止しました。通常の配置編集は表示ページ、AIは選択した範囲だけを変更します。「全ページを対象」を選んだ場合だけ全体を再計画します。枠数テンプレート変更は表示ページ以降を詰め直し、それより前のページと原文・作画を保持します。旧確定データは移行時に除去され、解除操作は不要です。個別の吹き出しロックは従来どおり有効です。
### 原稿更新は手動で確認

「接続・人物設定 → GitHub側の更新を確認」で、現在の作品・話だけを確認します。「更新なし」「差分あり」「確認失敗」を表示し、場面・設定・参照画像の差分概要を確認して「取り込む」で採用します。起動時・定期確認は行いません。未取込みの候補は終了時に消え、旧漫画が参照する取り込み済み原稿版は保持します。

原稿の共通契約と人物参照宣言は[設計正本の原稿インターフェース](docs/IMPLEMENTATION_PLAN.md#41-正本と参照)を参照。現行アプリの同期はstory-source/v1、schema 1、既存schema 4に対応します。schema 5のように本文・設定パスを宣言しない形式は未対応として明示します。

## 原稿の範囲を追加して制作する

「原稿と漫画への反映状態」で未反映の範囲を選択すると、処理中にも別の範囲を追加できます。共有コマや配置に依存する範囲は待機し、独立した範囲は同時に更新案を計画します。外部LLMは接続設定で1件ずつ／最大2件を選択でき、ローカル推論は1件ずつです。生成速度の倍率を保証する設定ではありません。

各範囲で更新案を確認し、必要な作画だけを生成してから適用します。個別停止・全停止後も候補と完成素材は残ります。独立範囲の先行適用後は依存を再検査して残りを適用でき、実際に原稿・参照・対象が変わった候補は再確認が必要です。応答未確定の画像要求は既存の結果復旧を使い、自動再送しません。
